# 黑马记账 - 产品文档

## 一、产品概述

**产品名称**：黑马记账  
**产品定位**：一款简洁、实用的个人记账桌面应用  
**目标平台**：Windows 电脑 + Mac 电脑  
**货币单位**：人民币（¥ / CNY）  
**目标用户**：有日常记账需求的普通用户，无需专业财务知识

---

## 二、核心功能模块

### 2.1 记账（核心功能）
- 记录每一笔花销，包含以下字段：
  - **金额**：支出金额（元），支持小数点后两位
  - **一级分类**：支出大类
  - **二级分类**：支出小类
  - **日期**：支出日期，默认当天
  - **备注**：可选文字备注
- 支持新增、编辑、删除账单记录

### 2.2 账单列表
- 按时间倒序展示所有账单
- 支持按日期范围筛选
- 支持按分类筛选
- 显示每日/每月合计

### 2.3 统计分析
- 饼图：按分类查看支出占比
- 柱状图/折线图：月度支出趋势
- 分类排行榜

### 2.4 预算管理（可选，二期）
- 设置月度预算上限
- 显示已用额度与剩余额度
- 超预算提醒

### 2.5 数据管理
- 数据本地存储（无需联网）
- 数据导出（CSV 格式）
- 数据备份与恢复

## 四、技术方案选型

> ⚠️ 以下方案均满足 Windows + Mac 双平台运行。请你阅读后选择你倾向的方案。

---

### 方案A：Electron + React + TypeScript

**简介**：使用 Web 技术（HTML/CSS/JS）开发界面，通过 Electron 框架打包成桌面应用。相当于把一个网页装进了桌面程序的外壳里。

| 优势 | 劣势 |
|------|------|
| ✅ 技术最成熟，社区资源最丰富，遇到问题容易找到解决方案 | ❌ 应用体积较大（约 100MB+） |
| ✅ 界面可以做得非常精美，动画丰富 | ❌ 内存占用相对较高（通常 100MB-300MB） |
| ✅ 开发效率高，插件和模板多 | ❌ 启动速度稍慢（3-5秒） |
| ✅ 跨平台兼容性好，Windows/Mac 表现一致 | |
| ✅ 有大量成熟的可复用组件 | |

**适合谁**：追求界面美观、功能丰富，不介意应用体积稍大的用户。

---

### 方案B：Tauri + React + TypeScript（推荐 ⭐）

**简介**：新一代桌面应用框架。界面同样用 Web 技术开发，但底层利用操作系统自带浏览器内核，打包体积非常小。后端逻辑用 Rust 语言（高性能）编写。

| 优势 | 劣势 |
|------|------|
| ✅ 应用体积极小（约 5MB-15MB） | ❌ 生态较新，部分进阶功能可能需要自研 |
| ✅ 内存占用低（通常 50MB-100MB） | ❌ 开发脚手架相对 Electron 少一些 |
| ✅ 安全性更高 | |
| ✅ 启动速度快 | |
| ✅ 安装包小巧，用户体验更好 | |

**适合谁**：追求轻量、快速、省资源的用户。这也是目前桌面应用的新趋势。

---

### 方案C：Flutter Desktop + Dart

**简介**：Google 推出的跨平台框架，一套代码可运行在手机、电脑、网页上。界面使用 Flutter 自有渲染引擎绘制，风格统一。

| 优势 | 劣势 |
|------|------|
| ✅ 一套代码未来可扩展为手机版（Android/iOS） | ❌ 桌面端生态还在完善中 |
| ✅ 界面风格统一，不依赖系统浏览器 | ❌ 应用体积中等（约 50MB-80MB） |
| ✅ 热重载开发体验好 | ❌ Windows/Mac 桌面端有一些平台特定问题 |
| | ❌ Dart 语言开发者相对较少 |

**适合谁**：如果未来有计划推出手机版 APP，这个方案最有扩展潜力。

---

### 三方案对比总结

| 维度 | 方案A Electron | 方案B Tauri ⭐ | 方案C Flutter |
|------|:---:|:---:|:---:|
| 应用体积 | 大 (~100MB) | 小 (~10MB) | 中 (~60MB) |
| 内存占用 | 较高 | 低 | 中等 |
| 启动速度 | 较慢 | 快 | 快 |
| 界面精美度 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ |
| 成熟稳定性 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐ |
| 手机端扩展 | 不直接支持 | 不直接支持 | ⭐⭐⭐⭐⭐ |
| 学习/维护成本 | 低 | 中 | 中高 |

---

### 我的推荐

> **推荐方案B（Tauri + React）**：对于一款记账应用，轻量、快速启动、低资源占用是很好的体验。打开就能记，不拖累电脑。同时界面可以做得美观现代。如果未来不考虑出手机版，这是最佳选择。
>
> 如果未来明确要出手机版，则推荐方案C（Flutter）。

## 五、项目规则（重要！）

### 5.1 技术决策规则 🔴

**在整个项目开发过程中，关于技术方面的任何决定，不能由开发一方单方面做出。**

具体规则如下：
1. 涉及技术选型、工具选择、架构设计、第三方库选择等技术决策时，必须给出 **2-3 个备选方案**。
2. 每个方案需要包含：
   - 方案的简要说明（用通俗易懂的语言）
   - 方案的优势（列出具体优点）
   - 方案的劣势（列出具体缺点）
   - 推荐意见（可标注推荐方案及理由）
3. 由用户（产品方）阅读方案后做出最终决定。
4. 用户决定后，记录决定内容到本文档的「决策记录」章节中。

### 5.2 产品规则
- 所有货币单位为人民币（¥），金额精确到小数点后两位
- APP 名称固定为"黑马记账"，不可更改
- 需支持 Windows 和 Mac 双平台
- 数据本地存储，无需联网，不收集任何用户数据

### 5.3 开发规则
- 所有修改需先得到用户确认
