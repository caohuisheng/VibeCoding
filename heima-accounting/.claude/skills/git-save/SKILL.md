# Git Save — 提交并推送代码

此技能用于将工作区中的代码变更提交（commit）并推送到远程仓库（push）。

## 前置条件

- 当前目录必须是一个 git 仓库
- 远程仓库已配置（`git remote -v` 有输出）
- 工作区中有待提交的变更（tracked 文件有修改，或有 untracked 文件）

## 执行流程

### 第一步：检查当前状态

```bash
git status
git branch --show-current
```

确认当前分支和工作区状态。

### 第二步：确认变更内容

向用户展示待提交的文件列表，请用户确认是否提交。

- **已修改文件**（modified）→ 展示文件列表
- **新增文件**（untracked / new file）→ 展示文件列表
- **已删除文件**（deleted）→ 展示文件列表

如果用户不想提交某些文件，在 `git add` 时排除即可。

### 第三步：暂存文件

```bash
# 暂存所有变更（包含未跟踪的新文件）
git add -A

# 或者选择性暂存
git add <file1> <file2> ...
```

### 第四步：生成提交信息并提交

根据变更内容，用中文生成清晰的提交信息。遵循以下格式规范：

- 使用**中文**描述变更
- 采用 `<类型>：<简述>` 格式
- 类型可选：`新增`、`修复`、`优化`、`重构`、`文档`、`配置`、`删除`

示例：
```
新增：记录收入功能
修复：账单列表日期排序错误
优化：分类筛选性能
重构：提取数据库操作模块
文档：更新 CLAUDE.md 决策记录
配置：添加 git-save 技能
```

```bash
git commit -m "<提交信息>"
```

### 第五步：推送到远程仓库

```bash
git push origin <当前分支名>
```

#### 如果推送失败（远程有新提交）

先拉取远程更新。推荐使用 rebase 模式保持提交历史整洁（个人项目）：

```bash
git pull --rebase origin <当前分支名>
```

如果有冲突，告知用户冲突文件，协助解决后继续：

```bash
# 解决冲突后
git add <冲突文件>
git rebase --continue
git push origin <当前分支名>
```

如果用户偏好保留合并记录，也可使用 merge 模式：

```bash
git pull origin <当前分支名>
# 解决冲突后
git push origin <当前分支名>
```

### 第六步：确认结果

推送成功后，向用户展示：

- 提交的分支名
- 提交信息
- 变更文件数量
- 推送结果（成功/失败）

## 注意事项

1. **提交前确认**：暂存文件前必须让用户确认变更范围，不要直接 add 全部文件。
2. **提交信息质量**：提交信息应当清晰描述"做了什么"，方便日后查看 git log。
3. **敏感文件**：检查是否有不应提交的文件（如 `.env`、`node_modules/`、`target/` 等），提示用户确认。
4. **大文件**：如果单个文件超过 10MB，提示用户考虑使用 Git LFS 或确认是否需要提交。
5. **冲突处理**：pull --rebase 时如有冲突，列出冲突文件，帮助用户解决后再推送。
6. **推送失败**：如果因权限问题推送失败，提示用户检查远程仓库权限配置。
